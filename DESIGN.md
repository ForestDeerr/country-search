# Design

## 1. Отмена HTTP-запросов (AbortController)

Для отмены HTTP-запросов используется `AbortController`.

При каждом изменении поискового запроса в `main.ts` вызывается `controller.abort()`, который отменяет предыдущий запрос, если он ещё выполняется.

После завершения задержки `debounce` создаётся новый экземпляр `AbortController`. Его свойство `signal` передаётся в функцию `searchCountries` и далее используется в `fetch`.

Такой подход позволяет:

- Отменять ненужные запросы при изменении поисковой строки.
- Не тратить ресурсы на получение устаревших результатов.
- Избегать отображения результатов предыдущего запроса.

Ошибка с именем `AbortError` обрабатывается отдельно и не приводит к обновлению результатов.

## 2. Debounce

Для поиска используется функция `debounce` с задержкой **500 миллисекунд**.

Запрос к API отправляется только после того, как пользователь перестал вводить текст на протяжении 500 миллисекунд.

Это позволяет уменьшить количество HTTP-запросов и снизить нагрузку на API.

Особенности выбранной задержки:

- Без `debounce` каждый ввод символа приводил бы к отдельному запросу.
- Меньшая задержка сделала бы поиск быстрее, но увеличила бы количество запросов.
- Большая задержка уменьшила бы количество запросов, но сделала бы интерфейс менее отзывчивым.

Значение 500 мс обеспечивает баланс между скоростью поиска и количеством запросов.

## 3. Сложность алгоритма (Big O)

Функция `mapCountryResponse` преобразует данные страны, полученные от API, в структуру `Country`, используемую приложением.

**Временная сложность: O(n)**

Где `n` — количество языков страны.

Это связано с использованием метода `map`, который один раз проходит по массиву языков и формирует новый массив с их названиями.

**Пространственная сложность: O(n)**

Для хранения нового массива названий языков требуется дополнительная память, пропорциональная количеству элементов исходного массива.

Остальные операции по копированию свойств объекта имеют сложность O(1).

## 4. Принципы Clean Code

При разработке приложения применяются следующие принципы:

- **Single Responsibility Principle (SRP):** каждая функция отвечает за одну задачу. Например, `searchCountries` выполняет HTTP-запрос, `mapCountryResponse` преобразует данные, а `createCountryCard` создаёт карточку страны.
- **Разделение ответственности:** логика запросов, преобразование данных, создание DOM-элементов и управление поиском находятся в отдельных модулях.
- **Понятные имена:** функции и переменные имеют имена, отражающие их назначение.
- **Переиспользование кода:** вспомогательные функции, такие как `debounce` и `mapCountryResponse`, независимы от основного интерфейса.
- **Типизация:** TypeScript используется для определения типов данных и проверки корректности их использования.
- **Безопасная работа с DOM:** элементы создаются с помощью `document.createElement`, текст добавляется через `textContent`, вместо использования `innerHTML`.
- **Неизменяемость данных:** `mapCountryResponse` создаёт новый объект, не изменяя исходный ответ API.

## 5. Обработка ошибок

В приложении предусмотрены отдельные типы ошибок:

- `HttpError` — ошибки HTTP-ответов.
- `AbortError` — ошибки отмены запросов.
- `TimeoutError` — ошибки превышения времени ожидания.

Особенности обработки:

- HTTP-ответ со статусом 404 рассматривается как отсутствие результатов поиска и возвращает пустой массив.
- Другие HTTP-ошибки обрабатываются с помощью `HttpError`.
- Ошибка отмены запроса `AbortError` обрабатывается отдельно в `main.ts`.
- Сетевые ошибки и другие необработанные ошибки передаются вызывающему коду.
